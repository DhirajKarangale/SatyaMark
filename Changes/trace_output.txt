# Detailed Code Changes - August 2026

*The following changes have been meticulously extracted by analyzing the actual file diffs present in the `git-work-report` files. This highlights exactly what logic was modified in the codebase.*

## 1. AI Text Verification Pipeline (Python)
- **`AI/text/starter/text_verify.py` (Complete Overhaul):**
  - Replaced the linear script execution with a LangGraph `StateGraph`.
  - Implemented the `GraphState` dictionary to pass data (`statement`, `summary`, `claims`, `result`) seamlessly between nodes.
  - Added four distinct processing nodes:
    - `summarize_node`: Calls the summarizer to condense the raw input.
    - `verifyability_node`: Evaluates if the statement is an objective fact. If the LLM flags it as `UNVERIFYABLE` (e.g., a subjective opinion), the script short-circuits and ends the graph early to save compute.
    - `decompose_node`: Uses an LLM to split the summary into an array of isolated, atomic claims.
    - `verify_claims_node`: Iterates over the atomic claims, running `fact_check()`. If the LLM returns "Insufficient", it falls back to `web_verify()`. It then aggregates the scores and URLs into a final JSON verdict.
- **`AI/text/starter/text_worker.py` (Concurrency Upgrade):**
  - Replaced the single-threaded blocking Redis listener with a `concurrent.futures.ThreadPoolExecutor(max_workers=5)`.
  - Modified `fetch_and_process()` to use `executor.submit(process_job_async)` so the main loop can immediately fetch the next job from Redis streams (`xreadgroup`), greatly improving concurrency.
  - Introduced `RedisProxy` to wrap the `redis` client to automatically handle and recover from ephemeral network drops.
- **`AI/text/summary/prompts.py` (Prompt Engineering):**
  - Rewrote the system prompts for text cleaning and summarization. Added strict instructions (e.g., "FAITHFUL PARROT semantic normalization") to prevent the LLM from hallucinating or altering proper nouns, and instructed it to convert all imperial units to global SI units.
- **`AI/text/verification/decompose.py` (New Module):**
  - Created this module to handle complex sentences. It takes a multi-faceted statement (e.g., "Apple was founded in 1976 in London") and splits it into an array of simple atomic claims, ensuring each claim can be fact-checked independently.

## 2. React SDK / Library (`satyamark-react`)
- **`Frontend/satyamark-react/src/core/process.ts` (Core Logic Fixes):**
  - **MutationObserver Fix**: Added logic to explicitly check if DOM mutations are occurring inside `[data-satyamark-status-container]`. If they are, it ignores them. This fixed a critical infinite render loop that was locking up the browser CPU.
  - **LRU Cache Implementation**: Added a `verificationCache` `Map`. If the map size exceeds `MAX_CACHE_SIZE = 500`, it dynamically deletes the oldest key (FIFO) to prevent memory leaks in infinite-scroll feeds.
  - **Async Hashing**: Upgraded the content hashing function to `await generateHash(text + image_url)` (utilizing WebCrypto SHA-256) instead of using an older, synchronous 32-bit integer bitwise shift.
- **`Frontend/satyamark-react/src/core/connectionManager.ts` (Security & Stability):**
  - **Cryptographic Payloads**: Integrated the WebCrypto API (`crypto.subtle`). It now imports a session-specific `hmacSecret` during the WebSocket handshake, and calls `signPayload()` to generate an HMAC SHA-256 signature for every outgoing job payload (`clientId:sessionId:jobId`).
  - **Keep-alive Ping/Pong**: Added `startPing()` and `stopPing()` functions. It sets a `setInterval` to send a `{"type": "ping"}` every 25 seconds. If a pong is not received, a 5-second `pongTimeout` triggers to forcefully close and reconnect the socket, solving the issue of silent network drops.
- **`Frontend/satyamark-react/src/utils/manageSessions.ts`:**
  - Upgraded session storage. Replaced `getSessionId` with `getSessionData`, which now securely encrypts and stores both the `sessionId` and the new `hmacSecret`.

## 3. Node.js Backend
- **`Backend/src/starter/ws-server.js` (HMAC Verification):**
  - Updated the WebSocket message handler to verify the HMAC signature of incoming requests. It uses Node's `crypto.timingSafeEqual` to compare the provided signature against the `hmacSecret` stored on the socket object, strictly protecting against timing attacks and forged requests.
  - Added logic to generate a new `hmacSecret` for every new connection and pass it down securely in the `session_created` or `session_confirmed` handshake response.
- **`Backend/src/utils/connectionManager.js` & `db.js` & `redisClient.js` (Proxy Wrappers):**
  - Created a highly robust custom `ConnectionManager` class that inherits from `EventEmitter`.
  - Wrapped the PostgreSQL `pool` and Redis `client` in ES6 `Proxy` objects.
  - **Proxy Logic**: The `get()` trap intercepts calls like `pool.query()`. If the connection status is `disconnected`, the proxy `await`s the `ensureConnection()` promise. This effectively pauses database queries until the connection is restored, completely eliminating fatal server crashes caused by DB timeouts.
- **`Backend/src/utils/process_task.js` (Cache Accuracy Fix):**
  - Changed the PostgreSQL cache hit logic. It now strictly checks `text_hash` and purposefully ignores `summary_hash`. This fixes false-positive cache hits caused by punctuation stripping (which previously made the system confuse a statement with a question).
- **`Backend/src/utils/enqueueJob.js` & `callback.js` (Job Stability):**
  - Fixed a critical bug in the Redis Streams producer. Added the missing `callback_url` parameter to the `xAdd` payload so that the Python AI workers know where to send HTTP POST responses.
  - Updated `callback.js` to correctly classify specific strings like "internal error occurred" as true AI processing failures rather than generic incorrect marks.

## 5. End-to-End Tracing System
- **`Backend/src/utils/tracer.js`**: Created a centralized trace aggregation sink. Generates sequential `trace_satyamark_*.json` files. Groups events by `jobId` and safely writes to disk without race conditions using `fs.writeFileSync(..., { flag: 'wx' })` and retry loops.
- **Frontend Buffering (`connectionManager.ts` & `process.ts`)**: Captured `sdk_initialized` and `websocket_connecting` events before jobs exist, buffering them locally and injecting them once a job is sent for perfect chronological timelines.
- **Redis & WS Introspection (`enqueueJob.js` & `ws-server.js`)**: Added explicit telemetry for backend HTTP/WS arrival, payload validation, memory-based Redis cluster selection (`RENDER` vs `UPSTASH`), and `xAdd` stream insertion.
- **Python Stream Consumption (`text_worker.py`)**: Added detailed telemetry for `xreadgroup` polling, capturing exact `msg_id`s, job parsing, HTTP callbacks, and final `xack` completions.
- **AI Deep Introspection (`text_verify.py` & `verifier.py`)**: Passively instrumented LangGraph routing decisions, web search queries, chunk relevance evaluations, and Map/Reduce evidence extraction states into the central trace via `contextvars`.
