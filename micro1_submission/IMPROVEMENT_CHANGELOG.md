# SatyaMark: Improvement Changelog

This changelog demonstrates the evolution of SatyaMark from a basic prompt to a robust, distributed agentic workflow capable of multi-modal content verification.

| Stage | What You Tried and Why | Evidence | Decision / Learning |
| :--- | :--- | :--- | :--- |
| **Baseline** | **Single LLM Prompt:** Started by passing social media posts directly to a large language model (Claude/GPT) and asking if it was "True or False". We wanted a simple, fast fact-checker. | The LLM confidently hallucinated answers for recent events (post-training cutoff) and failed completely when asked to verify image authenticity. | **Discarded.** A basic prompt lacks the context and tools required for real-world verification. |
| **Iteration 1** | **RAG & Web Search Tool:** Added a Google Serper API tool and Trafilatura web scraper so the LLM could fetch live context before answering. | Accuracy on recent news improved dramatically. However, the system wasted expensive compute time and API credits trying to "verify" subjective opinions and jokes. | **Revised.** We needed a way to drop subjective claims before running heavy evidence retrieval. |
| **Iteration 2** | **LangGraph StateGraph & Decomposition:** Migrated to an agentic state-machine. Added a `verifyability_node` to drop subjective opinions early. Added a `decompose_node` to split complex sentences into atomic, testable claims. | See `trace_output.txt`. The agent intelligently short-circuited on opinions, saving ~40% compute time. Fact-checking accuracy on complex, multi-faceted claims spiked because the agent handled them piece-by-piece. | **Kept.** The LangGraph architecture proved highly reliable and observable. |
| **Iteration 3** | **Handling Deepfakes & UI Blocking:** Added a fallback architecture for image verification (APIs -> 22+ local heuristics like ELA, PRNU). Realized that processing these heavy tasks synchronously locked up the user's browser. | The host React application would freeze for 5-10 seconds while waiting for the Python AI pipeline to finish. | **Revised.** We needed to decouple the heavy agentic processing from the user interface. |
| **Final** | **Distributed Async Orchestration:** Built a Node.js orchestrator. The React SDK offloads DOM extraction, while Redis Streams queues jobs for asynchronous Python workers. Added end-to-end tracing to capture every agent decision. | The host UI remains fully responsive. Traces accurately capture LangGraph routing, tool calls, and final WS broadcast back to the specific client. | **Final Solution.** A truly scalable, multi-modal verification infrastructure providing a universal mark of truth. |

### Main Failure Mode & Hot Take
* **Main Failure Mode:** Initially, the system treated "Unverifiable" (subjective) and "Incorrect" (factually wrong) as the same failure state. This eroded user trust, as an opinion isn't necessarily a lie.
* **Hot Take:** The biggest bottleneck in AI fact-checking isn't the LLM's reasoning capability; it's the lack of structured, atomic claims. If you don't decompose a user's multi-faceted paragraph into distinct, independent statements *before* you retrieve evidence, even the most advanced agent will fail to verify it accurately.
